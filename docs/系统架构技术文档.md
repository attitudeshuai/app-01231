# 图书管理系统技术架构文档

## 1. 项目概述

本系统是一个现代化的图书管理系统，采用前后端分离架构，提供完整的图书管理、借阅管理、用户权限管理和系统管理功能。

### 1.1 技术栈

| 层级 | 技术栈 |
|------|--------|
| 前端 | Vue 3 + TypeScript + Vite 5 + Element Plus + Pinia + Vue Router 4 + Axios |
| 后端 | Java 17 + Spring Boot 3.2.0 + MyBatis 3.0.3 + Spring Security + JWT |
| 数据库 | MySQL 8.0 |
| 部署 | Docker + Docker Compose + Nginx |

### 1.2 服务端口

| 服务 | 端口 | 说明 |
|------|------|------|
| 前端 | 8081 | http://localhost:8081 |
| 后端 API | 9999 | http://localhost:9999/api |
| API 文档 | 9999 | http://localhost:9999/api/swagger-ui.html |
| MySQL | 3307 | MySQL 8.0 数据库 |

## 5. 用户认证与权限控制

### 5.1 认证机制

采用 **JWT (JSON Web Token)** 无状态认证方案。

#### 5.1.1 JWT配置

- **Token类型**: Access Token + Refresh Token 双Token机制
- **签名算法**: HS256 (HMAC-SHA256)
- **Token载体**: `Authorization: Bearer <token>`

#### 5.1.2 JWT Token内容

[JwtTokenProvider.java](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01231/app-01231-winter/backend/src/main/java/com/library/security/jwt/JwtTokenProvider.java) 生成的Token包含：

```json
{
  "userId": 1,
  "username": "admin",
  "roles": ["ADMIN"],
  "permissions": ["book:list", "book:create", "..."],
  "sub": "admin",
  "iat": 1717800000,
  "exp": 1717886400
}
```

#### 5.1.3 认证流程

1. 用户提交用户名、密码、验证码
2. 后端验证用户身份和验证码
3. 生成Access Token和Refresh Token
4. 前端存储Token到localStorage
5. 后续请求在Header中携带Token
6. JWT过滤器验证Token有效性
7. Token过期后使用Refresh Token刷新

### 5.2 登录用户信息

[LoginUser.java](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01231/app-01231-winter/backend/src/main/java/com/library/security/LoginUser.java) 实现Spring Security的 `UserDetails` 接口，封装：
- 用户基本信息（ID、用户名、邮箱、手机号、头像）
- 角色集合（roles）
- 权限集合（permissions）
- 账户状态

### 5.3 权限控制

采用 **RBAC (Role-Based Access Control)** 基于角色的访问控制。

#### 5.3.1 Spring Security配置

[SecurityConfig.java](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01231/app-01231-winter/backend/src/main/java/com/library/security/SecurityConfig.java) 核心配置：

- **无状态Session**: `SessionCreationPolicy.STATELESS`
- **CSRF关闭**: 前后端分离架构无需CSRF防护
- **白名单路径**: 登录、注册、Swagger等接口放行
- **JWT过滤器**: 在UsernamePasswordAuthenticationFilter之前添加
- **方法级权限**: `@EnableMethodSecurity` 启用注解权限控制

#### 5.3.2 权限注解使用

- `@PreAuthorize("hasRole('ADMIN')")`: 角色校验
- `@PreAuthorize("hasAuthority('book:create')")`: 权限校验
- `@PreAuthorize("hasAnyRole('ADMIN', 'USER')")`: 多角色校验

#### 5.3.3 前端权限控制

- **路由级**: 通过 `meta.roles` 配置路由访问权限
- **按钮级**: 通过 `hasPermission` 方法判断显示/隐藏
- **菜单级**: 根据用户角色动态渲染侧边栏菜单

### 5.4 安全防护

#### 5.4.1 XSS防护

- **前端**: 输入验证、输出转义
- **后端**: [XssFilter.java](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01231/app-01231-winter/backend/src/main/java/com/library/common/xss/XssFilter.java) 过滤器 + [XssHttpServletRequestWrapper.java](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01231/app-01231-winter/backend/src/main/java/com/library/common/xss/XssHttpServletRequestWrapper.java) 请求包装
- **响应头**: Spring Security配置XSS-Protection、Content-Security-Policy等

#### 5.4.2 SQL注入防护

- 使用MyBatis预编译语句（`#{}` 语法）
- 禁止字符串拼接SQL

#### 5.4.3 密码安全

- 使用BCrypt算法加密存储
- 密码强度校验

### 6.3 借书流程

[BorrowServiceImpl.borrowBook()](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01231/app-01231-winter/backend/src/main/java/com/library/module/borrow/service/impl/BorrowServiceImpl.java#L98-L148) 实现借书逻辑：

```
用户发起借阅请求
    │
    ▼
检查图书是否存在 ── 不存在 → 抛出 BOOK_NOT_EXIST 异常
    │
    ▼
检查图书是否上架 ── 已下架 → 抛出 DATA_ERROR 异常
    │
    ▼
检查库存是否充足 ── 不足 → 抛出 BOOK_STOCK_NOT_ENOUGH 异常
    │
    ▼
检查是否已借阅该书 ── 已借阅 → 抛出 BOOK_ALREADY_BORROWED 异常
    │
    ▼
检查借阅数量上限 ── 达到上限 → 抛出 BORROW_LIMIT_EXCEEDED 异常
    │
    ▼
扣减图书可用库存 (bookService.decreaseStock)
    │
    ▼
创建借阅记录
    - status = 0 (借阅中)
    - borrow_date = 当前时间
    - due_date = 当前时间 + defaultBorrowDays
    - renew_count = 0
    - fine_amount = 0
    │
    ▼
返回借阅记录ID
```

### 6.4 还书流程

[BorrowServiceImpl.returnBook()](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01231/app-01231-winter/backend/src/main/java/com/library/module/borrow/service/impl/BorrowServiceImpl.java#L150-L180) 实现还书逻辑：

```
用户发起还书请求
    │
    ▼
检查借阅记录是否存在 ── 不存在 → 抛出 BORROW_RECORD_NOT_EXIST 异常
    │
    ▼
检查是否已归还 ── 已归还 → 抛出 DATA_ERROR 异常
    │
    ▼
计算逾期罚款
    │  if (当前时间 > 应还时间):
    │      逾期天数 = 当前时间 - 应还时间
    │      罚款金额 = 逾期天数 × 每日罚款
    │
    ▼
更新借阅记录
    - return_date = 当前时间
    - fine_amount = 计算出的罚款
    - status = 1 (已归还)
    │
    ▼
恢复图书可用库存 (bookService.increaseStock)
    │
    ▼
还书完成
```

[BorrowServiceImpl.renewBook()](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01231/app-01231-winter/backend/src/main/java/com/library/module/borrow/service/impl/BorrowServiceImpl.java#L182-L210) 实现续借逻辑：

```
用户发起续借请求
    │
    ▼
检查借阅记录是否存在 ── 不存在 → 抛出 BORROW_RECORD_NOT_EXIST 异常
    │
    ▼
检查是否已归还 ── 已归还 → 抛出 BOOK_NOT_RETURNED 异常
    │
    ▼
检查续借次数 ── 已达上限 → 抛出 RENEW_LIMIT_EXCEEDED 异常
    │
    ▼
检查是否逾期 ── 已逾期 → 抛出 BORROW_OVERDUE 异常
    │
    ▼
更新续借信息
    - due_date = 原到期日 + renewDays
    - renew_count = renew_count + 1
    │
    ▼
续借完成
```

### 6.6 逾期处理

#### 6.6.1 定时任务更新逾期状态

[BorrowServiceImpl.updateOverdueStatus()](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01231/app-01231-winter/backend/src/main/java/com/library/module/borrow/service/impl/BorrowServiceImpl.java#L240-L245)

- **执行时间**: 每天凌晨1点（`0 0 1 * * ?`）
- **逻辑**: 将超过应还日期且状态为"借阅中"的记录更新为"逾期"状态

#### 6.6.2 到期提醒

[BorrowServiceImpl.sendDueReminder()](file:///d:/charles/program/ai/apps/02.work%20session/session-gsb0608/source%20code/app-01231/app-01231-winter/backend/src/main/java/com/library/module/borrow/service/impl/BorrowServiceImpl.java#L247-L269)

- **执行时间**: 每天上午9点（`0 0 9 * * ?`）

### 7.4 前端异常处理

- **200 (业务成功)**: 直接返回数据

## 8. 系统特色与设计亮点

### 8.1 自定义BaseMapper与BaseService

项目未使用MyBatis-Plus，而是自定义实现了通用的BaseMapper和BaseService，提供基础CRUD和分页功能，保持了代码的轻量可控。

### 8.2 双Token机制

Access Token + Refresh Token双Token设计，既保证了安全性（Access Token有效期短），又提升了用户体验（无需频繁登录）。

### 8.3 完善的异常处理体系

前后端均有完善的异常处理机制，后端统一封装异常响应，前端统一拦截并友好提示。

### 8.4 操作日志AOP

使用AOP切面实现操作日志自动记录，无需在业务代码中埋点。

### 8.5 定时任务

- 每日凌晨更新逾期状态
- 每日上午发送到期提醒

### 8.6 XSS防护

多层XSS防护机制：输入过滤、输出转义、安全响应头。
